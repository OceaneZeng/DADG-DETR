# M-OWODB control 结果：基础检测路径也会发生输入响应退化

核验日期：2026-11-10。附件：`consolem_control.log`。远端训练仓库 HEAD 为
`a9efc819924bf47239a8a9da1099c3f83856ca28`，与本次本地分析开始时一致。主方法没有
未提交修改；远端另有 baseline 子目录和未跟踪扩展/清理记录，不把它们当作主方法跑错。

结论：**关闭图路由和发现监督以后，第 2 轮仍出现大范围对图片像素不响应，说明
基础检测训练路径本身就能产生这类退化。第 3 轮只有部分恢复，检测 AP 未恢复。**
GNN 或伪未知不是这次现象发生的必要条件；还没有证明某个基础超参数或实现细节是唯一首因。

## 扩大到 256 张图的只读审计

在完整已释放训练清单中，用均匀分布的固定 256 个索引，包含 **721 个已知 GT**。
使用确定性验证变换及 eval 模式；128 张比较均值颜色，另 128 张与下一张真实图比较。
对照图 resize 到原 tensor 尺寸，固定 mask、位置编码和几何条件。所有替换只发生在探针，
没有改变训练/测试数据协议，没有读取未来类监督。

| 轮数 | 换均值颜色的框差中位数 | 此类框差 <1e-6 的案例 | 换另一真实图的框差中位数 | 此类框差 <1e-6 的案例 |
| --- | ---: | ---: | ---: | ---: |

对应 logits 的 <1e-6 案例比例相同。1e-6 是本次“几乎不变”的机制统计阈值，
不是通用性能验收阈值。这里的 256 张是训练侧诊断样本，不是替换作者测试集。
不同几何布局仍能产生不同预测，因此失去像素响应并不等于所有图片得到完全相同的框。

第 3 轮不能写成已经恢复：均值提高受少数有响应图片影响，仍有多数均值颜色对照
接近数值误差。额外保留中位数和比例，避免只看平均值漏掉这一现象。

第 2 轮的 encoder 输出差异逐层衰减。以不同真实图对照的中位数为例，6 层分别为：

也不支持未经对照直接删 encoder 层或替换归一化。

256 图的几何/类别覆盖为：

| 轮数 | 100 queries 的 raw IoU>0.5 覆盖 | 正确已知类别 Top50 覆盖 | Hungarian 匹配上的已知类 argmax 正确数 |

## 梯度和重计算检查

每份 checkpoint 上各检查两组训练图 `[0,7]`、`[3000,9000]`，同一 batch、相同 dropout
随机状态，分别开关 activation checkpointing，重算 loss 和全部参数梯度，不执行更新。

6 组比较的 loss 相同；梯度相对 L2 误差约 **4.32e-9–6.96e-6**，未发现数量级上的
梯度计算差异。这个有限对照不证明所有训练输入都等价，但没有证据优先关闭重计算。

以 `[0,7]` 这一组为例，已知检测目标传回 backbone 的梯度范数为：

```text
第 1 轮：4.2211
第 2 轮：1.1872e-6
第 3 轮：3.8016e-5
```

第 2 轮 encoder/decoder/头部仍有梯度，backbone / input projection 的梯度却很小，
与像素信息在 encoder 内衰减一致。这不是原 DDP 随机增强 batch 的重放，不能认定
这些数值就是当时 optimizer 实际收到的全局梯度。

全部远端探针只读取现有 checkpoint，在独立内存中前向/反向；没有 optimizer step、
没有写服务器源码或训练权重。每份权重检查前后的 SHA256 相同。

## 下一步优化的边界

先验证基础检测优化是否过于激进。准备的单因素对照把所有参数组学习率降为原来的 1/4：
主 lr 5e-5，backbone 5e-6，采样偏移/参考点 5e-6。保持 DINO、seed、作者完整数据、
双卡、每卡 batch 2、损失、裁剪、架构及 50 轮日程不变，仍固定 3 轮暂停。

这属于待检验的优化假设，**并未证明学习率是唯一根因，也没有已经改善 AP 的结果**。
当前全局 batch 为 4、早期学习不稳定，降低步长值得优先做便宜且可归因的对照；不能
据此把缩放后的数值说成作者原始超参数。

改变学习率会改变优化轨迹，新运行从同样的 DINO 初始化，使用独立目录，不能续旧
control 或旧 discovery 权重。已准备的入口是：

```bash
bash tools/owod/run_control_mowodb_3090.sh lr-quarter
```

启动、日志目录与暂停后决策见[运行说明](owod-control-mowodb-debug.md)。预算约 1–1.5 小时
加几分钟探针，结束后对完整作者 Known AP 和固定 256 图输入响应共同分析；不自动
扩展到 50 轮。较低学习率的早期 AP 可能收敛较慢，3 轮结果只能指导后续预算。

同时保留对基础实现/初始化及 encoder 更新路径的后续核查，不通过更换数据划分、
预训练检测器、batch 或多个稳定化开关混在一起获得难以归因的分数。
