# v5–v8 退化排查：检测器对图像内容失去响应

核验日期：2026-11-10。服务器：`toplab.billzhou233.moe`（`top@topsrv`）。

后续同配方纯监督 control 已完成三轮，256 图审计确认无图/发现监督时也会发生
输入响应退化，见 [control 实跑分析](owod-control-mowodb-analysis-20261110.md)。
下文保留此次早期排查当时的证据和实验建议，不能将尚待运行的描述当作最新状态。

本次结论是：**排序竞争是故障的一部分，但更基础的故障是训练后的检测器对图像
内容几乎不再响应。v8 压低 unknown 输出后，已知检测仍然退化。继续叠加排序、
objectness 或置信度损失，没有先解决这个问题。**

已定位到 encoder 内图像差异被逐层压小，尚未证明最初触发这一过程的唯一训练因素。
这份报告不引入新方法版本，不把机制诊断当成 AP 提升，也不建议直接继续 v8 全量训练。

## 2. 同轮次的真实成绩

以下为完成第 8 轮时的作者评估。Task 1 无 Previous AP，Current AP50 等于 Known AP50。
AP、Recall、precision 已乘 100；WI 保留原始比值，A-OSE 为计数。

| 实际实验 | Current / Known AP50 (%) | U-Recall (%) | unknown 输出数 | unknown precision (%) | WI@0.8 | A-OSE |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| v6 ramp | 0.097126 | 3.173242 | 452,439 | 0.163558 | 0.030287 | 1,817 |
| v7 objectness focal | 0.027922 | 4.708405 | 488,333 | 0.224847 | 0.023105 | 552 |
| v8 ranking | 0.156115 | 0.038593 | 5,478 | 0.164294 | 0.015646 | 7,969 |

这些实验整体都失败，但各指标并非逐版单调下降。v8 的已知 AP 高于这两组第 8 轮，
绝对值仍接近零，未知召回则大幅下降。作者口径有 23,320 个 unknown GT，v8 仅召回
9 个。WI 下降不能单独当作改善：未知召回几乎消失，A-OSE 反而上升。

退化不是仅由末轮某个偶发评估造成：

- v5 的 Known AP50 第 1/3/6 轮为 1.2215% / 0.5280% / 0.02843%。
- v6 第 2/3 轮约 1.5580% / 1.5571%，第 4 轮降至 0.2518%。与此同时，验证
  分类 loss 从 1.0592 升至 1.2092，bbox loss 从 0.8811 升至 0.9912。
- v7 objectness 第 3 轮为 0.001721%，第 5 轮为 0。
- v8 第 1/2 轮没有任何 unknown 输出，Known AP50 仍从 1.0228% 降至 0.3928%；
  验证分类 loss 从 1.1148 升至 1.2311，bbox loss 从 0.9716 升至 1.0913。
  因此 v8 早期的检测恶化不能解释为 unknown 抢走了已知输出名额。

服务器没有 `v7 confidence` 共同参照的实际结果，也没有 v8 guarded / combined 结果。
从实际跑过的 v7 objectness 到 v8 ranking，objectness 损失、novelty 归一化和排序损失
同时不同，不能把两组差值全部归因于排序单项。

## 3. 最直接的证据：换掉图片，v8 几乎不换预测

固定合法训练集索引 0、7、15、23，保持模型、分辨率、mask、位置编码不变，把
标准化后的图片像素替换为 0，即数据均值颜色。模型使用 eval 模式。
下表为四张图上的平均绝对差；框坐标为归一化 cxcywh，logits 是原始 logits。

| 权重 | 框坐标平均差 | 分类 logits 平均差 | encoder 输出平均差 |
| --- | ---: | ---: | ---: |
| v5，第 5 轮 | 7.03e-9 | 6.87e-8 | 7.62e-8 |
| v6，第 5 轮 | 3.90e-2 | 1.88e-1 | 1.84e-1 |
| v6，最新第 10 轮 checkpoint | 1.65e-8 | 1.27e-7 | 3.09e-7 |
| v7 objectness，第 8 轮 | 3.25e-3 | 2.11e-2 | 4.62e-2 |
| v8 ranking，第 5 轮 | 1.34e-7 | 9.05e-7 | 2.75e-6 |
| v8 ranking，第 8 轮 | 6.77e-8 | 6.02e-7 | 1.03e-6 |

v6 最新 `checkpoint.pth` 保存的零基 epoch 是 **9**，即完成第 10 轮训练。
现存 metrics 只有前 9 轮评估，不能把这份权重的诊断写成“第 9 轮评估结果”。

为排除纯色输入的特殊性，又比较了两张**不同真实训练图**（image IDs
2021000005、2021000007），只把第二张图 resize 到第一张的 tensor 尺寸，使几何条件相同。
该探针不使用 GT，也不改变训练变换或正式评测：

| 权重 | 两张真实图的框坐标平均差 | logits 平均差 | query 表示平均差 |
| --- | ---: | ---: | ---: |
| v6，第 5 轮 | 0.033182 | 0.183047 | 0.269257 |
| v8，第 8 轮 | 3.23e-8 | 3.52e-7 | 5.69e-7 |

这批 v8 预测主要随 query、几何和位置条件变化，对图片像素内容几乎不响应。
100 个框仍可能覆盖部分 GT，因此“raw 框覆盖不为零”不能证明检测器还在正常看图。

### 信息在哪里消失

真实图与均值颜色之间，v8 四层 input projection 的平均差仍约 0.23–0.64，
说明输入图片确实不同，骨干和投影仍能产生不同表示。
下面追踪两张真实图经每个 encoder block 的输出差（`norm2`，每 64 个空间 token
采一个位置，数值不是全空间的 AP 或分布统计）：

| encoder block（从 1 开始） | v6 第 5 轮 | v8 第 8 轮 |
| --- | ---: | ---: |
| 1 | 0.045158 | 0.007771 |
| 2 | 0.066697 | 0.006897 |
| 3 | 0.001568 | 0.002451 |
| 4 | 0.028600 | 3.75e-5 |
| 5 | 0.150069 | 3.30e-6 |
| 6 | 0.251664 | 6.91e-7 |

v8 在第 4 个 block 的 FFN / norm2 周围进一步强烈收缩图像差异，后两层继续衰减。
不能据此把某一层直接改名为唯一根因，或删除该层宣称修复；这些是训练后的状态证据。

还做了两项排除性检查：

- deformable attention 采样并非整体越界：v8 各层落在 [0,1] 范围内的加权采样质量
  约 0.70–0.97。该统计没有把所有有效框内采样都认定为有用语义。
- 服务器实际 CUDA 扩展在固定小张量上与 PyTorch 参考实现比较，前向最大绝对误差
  1.36e-7；value、location、attention weight 梯度最大误差分别为
  1.19e-7、1.91e-6、8.94e-8。未发现该案例中的扩展数值异常；不是所有输入的正确性证明。

## 4. 排序约束有效压低 novelty，但没有救回检测

使用同一组 32 张训练图、88 个已释放已知 GT、确定性验证变换：

| 权重 | raw IoU>0.5 覆盖 | 仅已知 Top50 正确类别覆盖 | 联合 Top50 正确类别覆盖 | 联合输出中的 unknown |
| --- | ---: | ---: | ---: | ---: |
| v5，第 5 轮 | 51/88 | 23/88 | 2/88 | 1,541/1,600 |
| v6，第 5 轮 | 60/88 | 39/88 | 15/88 | 1,469/1,600 |
| v7 objectness，第 8 轮 | 51/88 | 24/88 | 3/88 | 1,533/1,600 |
| v8 ranking，第 5 轮 | 48/88 | 11/88 | 11/88 | 27/1,600 |
| v8 ranking，第 8 轮 | 52/88 | 20/88 | 20/88 | 22/1,600 |

这些覆盖允许多框覆盖同一 GT，不是一对一 AP。v6 行来自服务器已有的同前缀诊断，
其余行是本次新读权重结果；不同轮次不能充当单因素因果对照。

v8 第 8 轮匹配 GT 上：

- 真实已知类别分数超过同 query unknown 分数，排序违反 **0/88**。
- matched novelty 平均 **0.01010**；已知类别 argmax 正确率仅 **34.09%**。
- matched objectness 为 **0.5263**，未匹配且重叠已知 GT 的槽位为 **0.5184**，
  两组区别很小。
- 移除 unknown 后覆盖仍为 20/88，说明这批权重的主要瓶颈已不是联合输出的未知竞争。

排序损失本身存在容易满足而不改善检测的路径：

```text
L_rank = softplus(a_n - log p_y)
```

降低 novelty logit `a_n` 就能减小该目标，即使正确已知类别条件概率 `p_y` 仍然很低。
`count` 归一化又降低低置信伪未知组的贡献。在表示不能区分物体时，压低 novelty
可以让排序统计变好，但不能恢复图像信息、类别识别和框质量。
本次结果与这个机制相符；缺少 v7 confidence 对照，不能把未知召回下降全部归因于
排序损失，或宣称其单项因果效应已被分离。

## 5. 伪未知候选受到已知物体局部污染

当前 `mine_candidates` 只用候选与已知 GT 的 **IoU > 0.3** 排除已知区域。
如果一个小框完全位于大物体内部：

```text
IoU = 小框面积 / 大框面积
intersection-over-candidate-area = 1
```

它可能轻易通过 IoU 排除条件。仅用两视图框一致性和区域显著性，也不能保证它是一个
独立未知物体。预测近似不随图像变化时，相近的固定框布局仍可能通过翻转匹配。

对诊断 JSON 中重新生成的 EMA 候选，只读取**已释放训练 GT**，计算候选面积被任一
已知 GT 覆盖的最大比例：

| 权重 | 候选数 | 至少 80% 候选面积落在某个已知 GT 内 | 候选平均置信权重 |
| --- | ---: | ---: | ---: |
| v5，第 5 轮 | 136 | 33（24.3%） | 0.2468 |
| v6，第 5 轮 | 37 | 12（32.4%） | 0.2053 |
| v7 objectness，第 8 轮 | 139 | 37（26.6%） | 0.3441 |
| v8，第 5 轮 | 144 | 80（55.6%） | 0.2466 |
| v8，第 8 轮 | 139 | 75（54.0%） | 0.2409 |

几何包含不是未知候选准确率：已知 GT 框内部也可能存在独立未知物体，不能把 75 个
全部定性为错误伪标签。但实际抽查明确显示车窗、车身、骑马者/马的局部等被选作
pseudo unknown，说明这种污染确实发生。没有读取未来类标注。

本地示意图：`output/analysis/v8-20261110/v8-candidate-overlap.png`。
绿色是已释放 GT；红色候选的至少 80% 面积落在某个已知 GT 内，黄色为其他候选。
图中标注 query ID 和上述面积比例。

v8 候选平均两视图一致性为 0.7771，高于 v6 这批候选的 0.5942；候选数量也更多。
这些机制数值同时发生在输入响应几乎消失的权重上，因此候选数、一致性、loss 通过
都不能充当发现质量或检测 AP 的证据。

匿名原型的最大槽位支持占比由 v6 第 5 轮的 **33.73%**，变为 v8 第 5 轮的
**68.60%**、第 8 轮的 **80.77%**。16 个槽都有支持不代表发现了 16 个语义类别。
在这种表示和候选状态下，继续做未知→已知快照继承没有足够的语义依据。

## 6. 梯度证据限制了哪些解释

在相同四张训练图上，以 eval 模型、实际保存的 EMA、保存的 epoch 和 train-mode
criterion 重算联合损失，分别对已知检测损失及发现损失求梯度，不执行更新。
这不是原随机增强批次或实际 DDP 梯度的重放。

v8 已知检测损失传回骨干的梯度范数为 2.09e-5–2.36e-4，v6 第 5 轮为
0.00306–21.00；与输入信息在 encoder 中衰减的观测一致。
v8 当前这批样本中，发现损失/检测损失的梯度范数比：

- encoder 为 0.031–0.111；decoder 为 0.028–0.273。
- discovery adapter 为 8.41–44.96；不同分支方向并不一致。

所以不能从 loss 量级、总 grad_norm 或这份晚期权重断言“GNN 梯度全面压倒基础检测”
已经得到证明。早期累计干扰仍可能存在，但需要早期状态及配对训练才能检验。
`feature_grad_scale=0.1` 尚不是经证实的修复方案。

## 7. 排查顺序和下一次预算

前面的路线主要围绕症状增加监督：v6 缩放早期伪标签贡献，v7 改 objectness/
置信权重，v8 改排序。在缺少同协议纯检测对照、输入敏感性和候选质量审计的情况下，
这些改动不足以建立故障归因，几次昂贵训练没有形成可确认的检测收益。

下一步优先建立**同一 M 配方的纯监督 Deformable DETR 诊断对照**。它是内部 control，
不是 ORE/OW-DETR 外部方法复现，也不是完整 OWOD 成绩。保留 DINO、训练清单、类别
顺序、batch、GPU 数、学习率和优化日程；新配置不接续旧版本 checkpoint。
如果同配方 control 也失去输入响应，先排查基础检测优化和 encoder；如果 control 正常，
再以相同初始检测权重逐项加入图/发现监督，定位最先造成输入响应下降的因素。

建议预登记首个 control 的 **3 轮诊断预算，约 1–1.5 小时**，以当前服务器吞吐估计，
不是本次已经执行的训练。保留每轮编号权重和 optimizer/scheduler，记录训练分类/框学习，
暂停后逐轮读回权重检查输入替换差和 encoder 各层图像差异。纯检测 control 没有
伪未知候选；候选的已知局部包含比例留待后续重新加入发现分支时审计。
若输入响应再次落到数值误差量级并持续出现，保存证据后停止该支；control 正常才值得
支付发现分支配对实验的额外预算。作者 AP 仍按固定诊断点完整报告，不挑测试集最佳轮次。
正式 50 轮任务链及完成标记不能被这次短诊断替代。

后续已补充[三轮 M-OWODB control 入口](owod-control-mowodb-debug.md)：
`tools/owod/run_control_mowodb_3090.sh`。它固定双 3090、每卡 batch 2，使用独立
日志/结果目录，自动保留前三轮权重并在暂停后运行只读输入诊断。本地入口验证与
服务器实际训练是两回事；该脚本的真实三轮结果仍待运行。

候选修正需同时考虑小框包含和独立物体质量，先用已释放训练标注与可审查图像验证。
本次 0.8 是审计统计门槛，不直接升格为正式挖掘阈值；简单排除所有包含框也可能损失
已知物体内部共现的真实未知。匿名原型在污染受控、检测表示恢复前不作为有效转化证据。

本次没有唯一首因的配对训练证据，也没有证明某个新方案能提高全量 AP；已有证据足以
否定“只压住 unknown 输出就解决问题”和“候选增多/排序违反减少就值得继续全量训练”。
